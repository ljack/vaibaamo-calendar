# Repository Guidelines

## Project Structure & Module Organization
- `src/` holds the React + TypeScript app. Pages live in `src/pages/`, shared components in `src/components/`, and reusable utilities in `src/lib/`.
- Unit/integration tests live alongside code as `*.test.ts(x)` under `src/`.
- End‑to‑end specs are in `tests/` (Playwright). Reports land in `playwright-report/`.
- Static assets are in `public/` (including `public/version.json` generated by scripts).
- Database changes go in `supabase/migrations/` as SQL files.
- Project docs live in `docs/`.

## Build, Test, and Development Commands
- `npm run dev` — runs Vite dev server and generates `public/version.json`.
- `npm run build` — builds TypeScript and Vite production bundle.
- `npm run preview` — serves the production build locally.
- `npm run lint` — runs ESLint over the repo.
- `npm test -- --coverage` — runs Vitest unit tests with coverage.
- `npm run test:integration` — runs Playwright tests.
- `npm run sync-events` — syncs event data via `scripts/sync-events.js`.

## Coding Style & Naming Conventions
- TypeScript + React (Vite). Use 4‑space indentation to match existing files.
- Component names are `PascalCase`; hooks/utilities use `camelCase`.
- Test files end with `.test.ts` or `.test.tsx` and mirror the feature they validate.

## Testing Guidelines
- Unit tests use Vitest + Testing Library. Coverage is expected to stay **90%+**.
- Run `npm test -- --coverage` before pushing UI or logic changes.
- Playwright tests (if added) should live in `tests/` and use clear, scenario‑based names.

## Commit & Pull Request Guidelines
- Commit messages are short, imperative, sentence‑case (e.g., “Add event maps…”).
- PRs should include a concise summary, test results, and screenshots for UI changes.
- Note any new Supabase migrations or RPC changes in the PR description.

## Deployment & Vercel
- Vercel CLI is available. Use `vercel ls` to list recent deployments for this project.
- Check a failing deployment with `vercel inspect <deployment>` and `vercel logs <deployment>` as needed.
- Preview protection bypass rules are documented in `docs/vercel_deployment_rules.md`.

## Security & Configuration Tips
- Environment variables live in `.env` (ignored). Key variables include `VITE_SUPABASE_URL` and `VITE_PUBLIC_SUPABASE_ANON_KEY`.
- For sensitive data (e.g., attendee emails), use Supabase RPCs with explicit permission checks.
